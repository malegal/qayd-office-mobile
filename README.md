# Qayd Office

تطبيق Android مبني باستخدام **Expo** و**React Native** لإدارة العمليات اليومية في المكتب القانوني.

## الوظائف الحالية

- تسجيل الدخول عبر Supabase Auth.
- عرض القضايا والملفات المهنية والجلسات.
- ترحيل جلسة جديدة بسرعة.
- تسجيل المصروفات.
- إنشاء رسوم وأتعاب للقضايا.
- تسجيل الدفعات المقبوضة وتحديث المتبقي.
- العمل دون اتصال على Android عبر SQLite.
- مزامنة تلقائية عند عودة الإنترنت مع منع تكرار العمليات ومعالجة تعارضات التعديل.
- حماية البيانات عبر RLS وعضوية المكتب.

## التشغيل محليًا

```bash
pnpm install
pnpm start
```

لتشغيل معاينة Expo على الويب:

```bash
pnpm dev:metro
```

ولتطبيق Android باستخدام Expo:

```bash
pnpm android
```

## متغيرات البيئة

يحتاج التطبيق إلى متغيري Supabase التاليين في ملف `.env` المحلي، ولا يجب رفع ملف `.env` إلى GitHub. أنشئ الملف يدويًا بالقيم المناسبة:

```env
EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your-publishable-key
```

## التحقق

```bash
pnpm check
pnpm vitest run
pnpm exec expo export --platform web
```

## ملاحظات أمنية

يجب عدم وضع مفاتيح الخدمة ذات الصلاحيات المرتفعة داخل تطبيق الهاتف. يستخدم التطبيق مفتاح Supabase العام فقط، بينما تفرض قاعدة البيانات الصلاحيات عبر RLS ودوال RPC الآمنة.

## 👨‍💻 دليل المطوّر (Developer Guide)

> هذا القسم موجّه لأي مطوّر يريد استكمال العمل على المشروع. كل ما تحتاجه موجود هنا.

### ما هو المشروع؟

تطبيق **«مكتب جاد الرب للمحاماة»** — تطبيق فريق المكتب (Expo / React Native). يعمل على:
- **الويب (PWA)** — يُنشر على Vercel.
- **Android / iOS** — عبر EAS Build أو `expo run`.

الخلفية (Backend) هي **Supabase** (PostgreSQL + Auth + RLS + RPC).

### شاشة الدخول الموحّدة (مهم جدًا)

التطبيق فيه **شاشة دخول واحدة فقط**: `app/index.tsx` (شعار «Q» في الأعلى). لا توجد شاشة ثانية.

فيها ثلاثة أوضاع (`Mode`) يتبدّل بينها المستخدم من نفس الشاشة:
1. **`join` (الافتراضي)** — الانضمام بكود دعوة `QYD-XXXX-XXXX` + الاسم + البريد/الهاتف + كلمة المرور.
2. **`login`** — الدخول بحساب موجود (بريد + كلمة مرور).
3. **`create`** — تأسيس مكتب جديد (للمالك فقط).

**تدفّق الانضمام:**
1. نحفظ «نيّة الانضمام» (الكود + الاسم) في التخزين المحلي عبر `setPendingInvite`.
2. نحاول `signInWithPassword`، وإن لم يوجد الحساب نُنشئه بـ `signUp`.
3. عند وجود جلسة، تستدعي `resolveMembership()`: تتحقق من العضوية، وإن لم توجد تُكمل قبول الدعوة المعلّقة (`acceptInvite`) أو تأسيس المكتب المعلّق.
4. إن فشل كل ذلك تظهر لوحة «لا توجد عضوية» **داخل نفس الشاشة** (مع إعادة المحاولة/تسجيل الخروج) — لا تحويل لشاشة أخرى.

> ⚠️ الملف `app/onboarding.tsx` أصبح مجرّد `Redirect` إلى `/` (للتوافق مع الروابط القديمة فقط). **لا تضع منطق دخول فيه.**

### البنية العامة

```
app/            شاشات expo-router (المسارات = أسماء الملفات)
  index.tsx     شاشة الدخول الموحّدة (الوحيدة)
  (tabs)/       التبويبات بعد الدخول: الرول، القضايا، المصروفات، المهام، المالية
  team.tsx      إدارة الفريق (للمالك فقط): دعوات، أدوار، إلغاء
lib/            منطق الأعمال
  supabase.ts       عميل Supabase (مع احتياطي URL/مفتاح anon للنشر بضغطة واحدة)
  office-onboarding.ts  createOffice / acceptInvite / createInvite / ... (RPC)
  office-data.ts        قراءة بيانات المكتب (مع كاش أوفلاين)
  office-permissions.ts خريطة الصلاحيات لكل دور
  pending-intent.ts     تخزين «نيّة الانضمام/التأسيس» محليًا
  offline-store.ts      تخزين أوفلاين (SQLite على الجهاز / AsyncStorage على الويب)
hooks/          use-supabase-auth، use-offline-sync، use-colors
components/     مكوّنات واجهة مشتركة (IconSymbol, HapticTab, ...)
public/sw.js    Service Worker يخدم قشرة التطبيق على أي رابط (يصلح 403)
app/+html.tsx   قالب HTML المخصّص (RTL + تسجيل الـ Service Worker)
```

### نموذج الأمان (مهم)

- تطبيق الهاتف **لا يكتب مباشرة** في جداول العمليات (القضايا/الجلسات/المصروفات...).
- كل عملية من الهاتف تتحوّل إلى سجل في `approval_requests` يراجعه المالك من تطبيق سطح المكتب.
- **الأدوار:** `manager` (المالك)، `lawyer`، `staff`، `accountant`، `member`.
- **عضو المكتب (`member`)** لا يرى: عدّاد القضايا، الأتعاب المتفق عليها، المحصّل، المتبقّي. يستطيع فقط: ترحيل الجلسات، البحث في قضايا المكتب، تسجيل الإجراءات والمصروفات. **ولا يستطيع الحذف.**
  - تُطبَّق هذه القيود عبر `lib/office-permissions.ts` (`canViewCaseCount`, `canViewFinance`, `canDelete`).
  - ⚠️ ملاحظة: دور `member` مدعوم في الواجهة، لكن يجب التأكد من دعمه في قاعدة البيانات (قيود الجدول + سياسات RLS) قبل استخدامه فعليًا.

### النشر على Vercel (خطوة بخطوة)

المشروع مهيّأ للنشر على Vercel مباشرة (ملف `vercel.json` موجود):

1. ادخل إلى [vercel.com](https://vercel.com) → **Add New → Project**.
2. اختر مستودع GitHub: `malegal/qayd-office-mobile` والفرع **`main`**.
3. إعدادات البناء تُقرأ تلقائيًا من `vercel.json`:
   - **Build Command:** `npx expo export --platform web`
   - **Output Directory:** `dist`
4. (اختياري) أضف متغيّرات البيئة في Vercel لو أردت تجاوز القيم الافتراضية:
   - `EXPO_PUBLIC_SUPABASE_URL`
   - `EXPO_PUBLIC_SUPABASE_ANON_KEY`
   > القيم الافتراضية مضمّنة في `lib/supabase.ts`، لذا سيعمل النشر حتى بدون إعدادها.
5. اضغط **Deploy**. سيحصل التطبيق على رابط عام جاهز للاستخدام.

### أوامر مفيدة

```bash
pnpm install                 # تثبيت الحزم
pnpm dev:metro               # تشغيل معاينة الويب محليًا
pnpm check                   # فحص الأنواع (tsc --noEmit)
pnpm build:web               # بناء نسخة الويب الثابتة إلى dist/
pnpm android                 # تشغيل على Android عبر Expo
pnpm test                    # تشغيل الاختبارات
```

### خطوات مقترحة لاستكمال العمل

- [ ] دعم دور `member` في قاعدة البيانات (قيود الجدول + سياسات RLS + RPC) وإظهاره في `app/team.tsx`.
- [ ] زر تسجيل خروج مباشر في شاشة الرول `(tabs)/index.tsx`.
- [ ] تحسين معالجة تعارضات المزامنة في `sync_conflicts`.
- [ ] إضافة اختبارات وحدات لخريطة الصلاحيات `office-permissions.ts`.

### ملاحظات للنشر

- ملف `.env` **لا يُرفع** إلى GitHub (مذكور في `.gitignore`). القيم الافتراضية في `lib/supabase.ts` تغني عنه عند النشر.
- مجلد `dist/` **لا يُرفع** (يُبنى تلقائيًا على Vercel).
- عند البناء لمسار فرعي (وليس الجذر) مرّر `EXPO_BASE_URL=/المسار` وقت البناء فقط.
